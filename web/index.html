Where your AI spend went.

Segreant reads the usage logs your AI tools keep on your computer, or sits between them and your provider. It shows what they cost, estimated from price lists or taken from your invoice, caps runaway spending on the requests it handles, and shows which spend went into work you kept. It all runs on your computer.

Try the demo See a sample month

No telemetry by default. Requests you route through Segreant still go to your AI provider. See what stays on your computer

Every figure says what kind it is.

List cost, billed cost, allocated cost and value answer four different questions. Segreant keeps them apart and labels each one, so an estimate from a price list never passes for your invoice, and money spent never passes for work done.

Count tokens, and people spend tokens.

AI coding agents bill by the token, and a stuck loop runs up the bill without a warning. When usage itself becomes the target, it gets worse: people chase the number.

In 2026, employees at Meta and Amazon built internal leaderboards ranking colleagues by AI tokens used. Amazon took its board, KiroRank, down after staff ran agents on low-value tasks to climb it and computing costs rose; a senior vice president asked staff not to use AI just for the sake of it. Meta's board was taken down in April.

A token count rewards spending more, not shipping more: a padded prompt scores the same as real work. Counting lines of code only rewards verbosity instead.

Latency and error dashboards can't see any of this. A request that costs $0.002 and a loop that costs $0.40 look the same to them. Segreant adds the cost, then shows what the cost went into.

Sources: CIO on KiroRank · Fortune on Meta's dashboard

Stop a runaway agent before the bill arrives.

For requests sent through Segreant, set a daily cap, a cap per agent session and a loop guard. A warning fires at the soft limit. At the hard limit Segreant refuses the request with a clear error instead of forwarding it.

$ segreant budget --daily 25 --soft 18 --runaway 2
--daily 25
Refuse requests once today's spend through Segreant reaches $25.
--soft 18
Warn at $18.
--runaway 2
Stop a loop that spends $2 within 60 seconds.
--session N
Cap a single agent session.

Caps cover requests sent through Segreant. They apply only when traffic is explicitly routed through Segreant. Usage imported from your tools' logs has already happened, so it can't be stopped and doesn't count toward a cap.

Caps are off until you set one. A fresh install measures but never blocks.

If Segreant can't read its settings or its ledger, it stops forwarding. A damaged configuration never turns into unlimited, unmeasured spending.

Each non-streaming response carries its cost in an X-Segreant-Cost-USD header. Streaming responses carry the remaining budget instead, because the cost isn't known until the stream ends; the final cost is recorded then.

Two ways in. Neither needs an account.

1Read the logs you already have

If you use Claude Code, Codex or opencode, Segreant reads the usage they already log on your computer, including subscription usage that a proxy never sees. Nothing needs rewiring.

# find your AI tools and repos; changes nothing
$ segreant scan
# import that usage, grouped by project
$ segreant scan --setup
# today's cost by model, project and tool
$ segreant today

2Route requests through Segreant

Point a tool at the local proxy to measure it as it runs and enforce caps. There's no certificate to install, and it sees only traffic you send to it. Segreant forwards each request to the provider you configure, and it starts locked: nothing is forwarded until you allow that route.

# proxy on :8090, dashboard on :8091
$ npm run start
# run one tool through it (or codex, opencode, aider)
$ segreant launch -- claude

Point segreant audit --repo at a repository and each commit gets the spend logged since the one before it, with the cost per 100 changed lines. Those two figures are all it reports: no invented efficiency score to chase.

Each routed call is priced against a dated price list and written to a ledger on your computer. Ordinary metering doesn't store prompt text in that ledger. The optional capture of the AI's suggestions, used to measure how much of them you accepted, stays on your computer and can be switched off.

A record you can hand to someone else.

For each piece of kept work, Segreant can issue a receipt: what it cost, the result of each check, and the outcome, signed with your ed25519 key. Anyone with your public key can confirm who issued it and that no byte has changed, without seeing your code.

The signature proves where the record came from, not that the checks inside were right. Those rest on the tests, deploys and history that produced them.

The arithmetic is published. Check it.

Every figure comes with the way it was worked out, and with what it can't tell you. A calculation on your computer is never presented as your provider's bill, or as proof that AI made you more productive.

Value score
Combines four measures so that one strong result can't hide a weak one. A measure you don't track stays open and is shown as missing; it is never scored as a pass.
95% range
The share of spend that went into kept work comes with a range that stays valid however often you check it. The cost is a slightly wider range.
Change alert
Fires when your kept-work rate shifts. It can't say why: a new model and a gamed number both set it off, and telling them apart takes evidence the rate doesn't carry.
Savings
Segreant doesn't promise a percentage. What you save depends on how much waste there was to find; its job is to show you where it is.

Built so developers want it switched on.

A cost tool that developers route around measures nothing. Personal views belong to the person. Team views are opt-in, show totals and spreads rather than individuals, and hide any group smaller than five people.

Team sync, when you turn it on, sends numbers only: no prompts, no code.

When two goals conflict, the higher one wins. This order is part of the design, not a promise added later.

It reads your logs and controls live traffic, on your computer.

Where it runs
Measurement, ledger and dashboard all run on your computer. Built on Node's own SQLite, with no runtime dependencies.
Stops spending
Daily, session and loop caps on the requests it handles.
Links cost to commits
Yes, from your local git history.
Telemetry
None by default: 0 bytes of Segreant telemetry or product analytics. No Segreant-hosted telemetry by default.
What it measures live
Streaming and non-streaming responses from supported providers, when traffic is explicitly routed through Segreant.
Accounts
None needed to run it. Your provider keys stay under your control.

See it on sample data first.

The demo runs on labelled sample data in its own database, so it never touches your real usage. No API key, no account. You need Node 24 or later.

Segreant isn't on npm yet, so start from the repository. Then open http://localhost:8091. When you move to real work, segreant guide reads your setup and names the next step.

$ git clone https://github.com/GamingDragonwastaken/Segreant.git
$ cd Segreant
# dev tooling only; no runtime packages
$ npm install
# sample data, opens the dashboard
$ npm run demo
